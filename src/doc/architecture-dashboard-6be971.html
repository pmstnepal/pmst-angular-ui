PostgreSQL Target Schema Design

👥 User Management

users table
  • • id (UUID, Primary Key)
  • • email (Unique, Indexed)
  • • username (Unique)
  • • password_hash (bcrypt)
  • • role (enum: admin, editor, user)
  • • created_at, updated_at
user_profiles table
  • • user_id (Foreign Key)
  • • display_name
  • • bio, avatar_url
  • • social_links (JSONB)

📝 Content Management

content table
  • • id (UUID, Primary Key)
  • • title, slug (Unique)
  • • content (TEXT)
  • • type (enum: post, page, event)
  • • status (enum: draft, published)
  • • author_id (Foreign Key)
  • • published_at
content_meta table
  • • content_id (Foreign Key)
  • • meta_key, meta_value
  • • Custom fields storage

🖼️ Media Management

media table
  • • id (UUID, Primary Key)
  • • filename, original_name
  • • mime_type, file_size
  • • s3_url, s3_key
  • • dimensions (JSONB)
  • • uploaded_by (Foreign Key)
media_galleries table
  • • id, gallery_name
  • • description
  • • created_by (Foreign Key)

🏷️ Taxonomy System

categories table
  • • id (UUID, Primary Key)
  • • name, slug (Unique)
  • • description
  • • parent_id (Self-referencing)
content_categories table
  • • content_id, category_id
  • • Many-to-many relationship

💬 Comments System NEW

comments table
  • • id (UUID, Primary Key)
  • • content_type ('article'|'gallery')
  • • content_id (Foreign Key)
  • • parent_id (Self-referencing for replies)
  • • author_id (Foreign Key to users)
  • • content, status, like_count
  • • created_at, updated_at, deleted_at
comment_likes table
  • • comment_id, user_id (Composite PK)
  • • Track user upvotes
comment_flags table
  • • id (UUID, Primary Key)
  • • comment_id, reporter_id
  • • reason, status, description

Data Mapping Strategy

👥 Users Migration

WordPress Source
  • • wp_users.ID → users.id
  • • wp_users.user_email → users.email
  • • wp_users.user_login → users.username
  • • wp_users.user_pass → users.password_hash (re-hash)
  • • wp_users.user_registered → users.created_at
PostgreSQL Target
  • • Convert ID to UUID
  • • Re-hash passwords with bcrypt
  • • Map user roles to new enum
  • • Create user_profiles from wp_usermeta

📝 Content Migration

WordPress Source
  • • wp_posts (type='post'/'page') → content
  • • wp_posts.post_title → content.title
  • • wp_posts.post_content → content.content
  • • wp_posts.post_name → content.slug
  • • wp_posts.post_status → content.status
  • • wp_posts.post_author → content.author_id
PostgreSQL Target
  • • Convert post_type to content.type
  • • Map post_status to new enum
  • • Extract postmeta to content_meta
  • • Handle featured images separately
  • • Preserve SEO metadata

🖼️ Media Migration

WordPress Source
  • • wp_posts (type='attachment') → media
  • • wp_posts.post_title → media.original_name
  • • wp_postmeta (metadata) → media.dimensions
  • • wp_upload_dir files → S3 storage
PostgreSQL Target
  • • Upload files to S3 during migration
  • • Generate S3 URLs and keys
  • • Extract EXIF data for images
  • • Create media galleries from wp_terms

💬 Comments Migration NEW

WordPress Source
  • • wp_comments → comments
  • • comment_ID → comments.id (UUID)
  • • comment_post_ID → content_id (map to new UUIDs)
  • • comment_parent → parent_id (nested replies)
  • • comment_author → author_id (registered users)
  • • comment_content → content
  • • comment_approved → status (1=approved, 0=pending)
PostgreSQL Target
  • • Map comment_post_ID to new content UUIDs
  • • Preserve nested reply structure
  • • Set content_type based on post_type
  • • Convert user_id for registered commenters
  • • Migrate commentmeta if exists
  • • Create comment_likes from any vote data
