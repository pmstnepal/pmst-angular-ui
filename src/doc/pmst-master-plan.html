Authentication Architecture

Recommended: Hybrid Approach

Approach: AWS Cognito + JWT Tokens

Cognito handles user registration, login, password reset, MFA, and social login. API Gateway validates JWTs. Lambda functions receive user identity in context.

Cognito Manages:

  • ✓ User registration / login
  • ✓ Password reset / recovery
  • ✓ Email verification
  • ✓ MFA (TOTP/SMS)
  • ✓ Social login (Google/Facebook)
  • ✓ Token lifecycle

Your Code Manages:

  • ✓ Business logic only
  • ✓ User profile data (PostgreSQL)
  • ✓ Content permissions
  • ✓ Custom claims (if needed)

User Profile Architecture

Two-Table Approach (WordPress-style)

  • users table: Auth data (id, cognito_id, email, username, role, status)
  • user_profiles table: Profile data (user_id FK, display_name, bio, avatar_url, cover_photo_url)

Why Separate Tables?

  • ✓ Clean separation (Cognito handles auth, PostgreSQL handles profile)
  • ✓ Flexible schema (add profile fields without touching users table)
  • ✓ Matches WordPress wp_users + wp_usermeta pattern
  • ✓ Easier to cache profile data separately

Data Flow

WordPress migration: wp_users → users
WordPress migration: wp_usermeta + wp_pmst_author_profiles → user_profiles
Backend: JPA @OneToOne loads profile with user
Backend: UserDto merges User + UserProfile data
Frontend: Angular receives single user object with displayName, avatarUrl, etc.

WordPress User Migration Strategy

RECOMMENDED

JIT (Just-In-Time) Migration

  • 1. User logs in with WordPress credentials
  • 2. Cognito UserMigration Lambda trigger fires
  • 3. Lambda validates against legacy phpass hash
  • 4. Cognito user auto-created — user sees nothing
Pros: Zero user friction. Same credentials they always used.
Status: Designed, not yet implemented. Phase 5 task before go-live.
ALTERNATIVE

Bulk Import + Email Reset

  • 1. Export all WP users to Cognito (no password)
  • 2. Every user gets "set new password" email
  • 3. Users must reset before logging in
  • 4. Simpler tech, no Lambda needed
Cons: Disruptive — all users forced to act

File: deploy/environments.yaml

All API calls returned 403 "Missing Authentication Token" during prerender. Root cause: apiUrl pointed to …/test but the API Gateway resource is mounted at /api/{proxy+}. Angular services appended paths directly, hitting non-existent routes. Fix: append /api to apiUrl for all environments.

Fix 1

SSR Prerender Crash — window is not defined

File: gallery-carousel.component.ts

Root cause: window.setInterval() called unconditionally — crashes in Node.js during prerender.

Fix: Guard with isPlatformBrowser(this.platformId) before any window usage.

// After
startAutoRotate() {
if (!isPlatformBrowser(this.platformId)) return;
this.autoRotateInterval = window.setInterval(...);
}

Pattern applies to all browser APIs: window, document, localStorage, navigator, IntersectionObserver, etc.
